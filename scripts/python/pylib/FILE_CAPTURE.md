# Lambda Blotto corpus-capture slice

This staged slice implements file observation and bounded hidden-aware directory traversal without writing into `cpg-highway`. Lambda Blotto is discrete Colonel Blotto; Lambda denotes spectral coordinates together with lambda-calculus motion, `delta` is the operational semantics, and this observe/run/seal path supplies explicit evidence effects for that integrated model.

Each named operation has an immutable `Input`, `Output`, `Effect`, and `Frame`, an `apply` projection, an exact external `PROJECT` leaf, and an operation identity. Each scheduler advances exactly one algebraic state per call. File and directory pre/post observations use `fstat` on the same open descriptor occurrence. End conditions are zero-byte read, observed pre-size, an explicit maximum-byte bound, or a directory end witness inside the explicit entry bound. Revision, transition-progress, and final receipt identities use SHA-256 gates and length-framed bytes.

Sparky is the active approximately-20K-file greenfield stateless graph machine before Phoenix. Every capture request therefore carries actual artifact provenance: source root, root key, mapping identity, revision reference, full drill-down chain, source kind/family/identity, claim key, volume/chapter/appendix route, immutable exact corpus occurrences, and evidence class. Each occurrence carries the exact source text, path, locus, revision, frame time, source kind, authority role and scope, resolution status, non-exclusivity, routed relation, claim classification, support boundary, and target volume/chapter/subsection. Its coordinate frame also binds semantic drill-down, diagram caption/label route, citation key, publication header, footer state, and readback artifact. File and directory receipts seal the complete occurrence tuple. Observed, Predicted, Counterfactual, and Admitted are distinct lineages. A Predicted or Counterfactual frame can be evaluated against a current boundary, but the receipt seal rejects it as Observed evidence. Scan identity, attempt, explicit counts, locator, and previous digest support orchestration at corpus scale without a module-global cursor.

The staged canonical route is `OUR ecosystem -> PHOENIX RUN [contains Molt D/R] -> Icarus -> Helios/GraphAtlas`. Molt is the disintegration/reassimilation mechanism inside the Phoenix Run. Icarus is the getting-to-the-sun vehicle: the custom VS Code/Protégé ecosystem integration and named reborn integration state, with Daedalus implicated. Helios/GraphAtlas is the mise-en-scène and accessible consolidated stage under construction. The routing ledger keeps these as distinct typed relations. It classifies the Volume 30 equivalence and consolidated route as declared synthesis, preserves the operator-ledger and live-source statements as direct source, preserves capture maps as maps, and binds every support boundary instead of laundering map prose into implementation proof.

Computing substrates are routed as an open coproduct of independently identified frames. `hardware_profile.html` contributes one time-scoped local observation containing a 12th-generation Intel CPU, AMI/UEFI-capable firmware, and an AMD display adapter; identifying fields are excluded. That frame is neither standards authority nor a corpus boundary. Separate resolved occurrences bind the RISC-V User ISA v2.1 artifact, AMD HIP/ROCm source bundle, MAPL 2019 Triton paper, Linux KVM paper, and a cross-family lexical map. Required Intel and AMD CPU-generation sweeps, other ISA systems, current CUDA/ROCm/Triton and further stacks, UEFI/firmware variants, KVM/QEMU/Proxmox and further VM/hypervisor frames, operating environments, networking/storage, and single-/multi-machine deployments remain typed `Admitted` discovery obligations wherever their exact loci have not yet been resolved. An unresolved row is a GAP, never an omission or fabricated observation.

Publication validation is navigable rather than title-only. Every occurrence belongs to exactly one coordinate frame from volume through chapter and subsection to semantic drill-down and diagram. The frame exposes the citation key and the occurrence keeps its exact source locus. Header source, rendered-footer state, and receipt readback are explicit. Citation closure is stronger than finding a bibliography key: it requires key resolution and rendered superscript numeric citation evidence. A missing chapter-local diagram or unbound rendered footer is recorded as a GAP rather than inferred away.

The directory scheduler explicitly supports `include-all`, so hidden capture roots are not filtered by accident. Each child is observed with `follow_symlinks=False`; symlinks are recorded and never followed. Regular files become typed file-capture frontier work, directories below the depth bound become typed directory frontier work, and every child preserves its map-to-target lineage and publication routing. The per-transition progress receipt binds scan identity, attempt, transition identity, from/to state, effect, and evidence class.

This is staged, not admitted. Descriptor linearity across independently hosted invocations remains a named gap. Directory-child `lstat` metadata is not yet rebound as an equality precondition when separately scheduled file work re-admits that path; a replacement becomes a fresh captured occurrence rather than a proof of identity with the parent observation. The executable extension uses the Python-safe `lambda_blotto` package segment and consumes Telephone's shared byte carrier through its project gate; it intentionally has no interpreter entrance. The whole-payload bounded accumulator is not represented as a serializable streaming SHA-256 state. File progress sealing and directory transition sealing create typed receipts but do not emit to the wire. `os.listdir` still materializes a whole fresh name vector before projecting one ordinal, and Python exposes no serializable kernel directory-snapshot token; these remain named gaps rather than hidden completeness claims.
